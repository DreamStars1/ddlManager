# 持久层架构设计 - 适配器模式

## 概述

本项目采用**适配器模式**实现持久层的解耦，使得 Service 层与具体的持久层框架（JPA/MyBatis）完全隔离。

## 架构设计

### 三层结构

```
┌─────────────────────────────────────────────────────────────┐
│                    Service 层（业务逻辑）                      │
│              只依赖 TaskRepositoryPort 接口                    │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│              TaskRepositoryPort（业务接口）                    │
│         定义所有数据访问操作的抽象方法                          │
└────────────────────────┬────────────────────────────────────┘
                         │
        ┌────────────────┴────────────────┐
        ▼                                 ▼
┌──────────────────────┐        ┌──────────────────────┐
│  JPA 适配器实现       │        │  MyBatis 适配器实现   │
│ (当前使用)           │        │  (预留实现)          │
│                      │        │                      │
│ TaskJpaRepository    │        │ TaskMyBatis          │
│ Adapter              │        │ RepositoryAdapter    │
└──────────────────────┘        └──────────────────────┘
        │                                 │
        ▼                                 ▼
┌──────────────────────┐        ┌──────────────────────┐
│  TaskRepository      │        │  TaskMapper          │
│  (JPA Repository)    │        │  (MyBatis Mapper)    │
└──────────────────────┘        └──────────────────────┘
        │                                 │
        ▼                                 ▼
┌──────────────────────┐        ┌──────────────────────┐
│      MySQL           │        │      MySQL           │
└──────────────────────┘        └──────────────────────┘
```

## 核心组件

### 1. TaskRepositoryPort（业务接口）

**位置**: `domain/task/repository/TaskRepositoryPort.java`

定义所有数据访问操作的抽象方法，Service 层只依赖此接口。

```java
public interface TaskRepositoryPort {
    Optional<TaskEntity> findById(Long id);
    Optional<TaskEntity> findByUuid(String uuid);
    TaskEntity save(TaskEntity task);
    void deleteById(Long id);
    // ... 其他方法
}
```

**特点**:
- 纯业务接口，不包含任何框架特定的注解
- Service 层唯一的数据访问依赖
- 与具体的持久层框架无关

### 2. TaskJpaRepositoryAdapter（JPA 适配器）

**位置**: `infrastructure/persistence/jpa/TaskJpaRepositoryAdapter.java`

将 Spring Data JPA 的 TaskRepository 适配为 TaskRepositoryPort 接口。

```java
@Component
@Primary
public class TaskJpaRepositoryAdapter implements TaskRepositoryPort {
    
    private final TaskRepository taskRepository;
    
    @Override
    public Optional<TaskEntity> findById(Long id) {
        return taskRepository.findById(id);
    }
    // ... 其他方法实现
}
```

**特点**:
- 标记为 `@Primary`，表示默认使用此实现
- 直接委托给 JPA Repository
- 当前生产环境使用

### 3. TaskRepository（JPA Repository）

**位置**: `domain/task/repository/TaskRepository.java`

Spring Data JPA 的 Repository 接口，定义 JPA 特定的查询方法。

```java
@Repository
public interface TaskRepository extends JpaRepository<TaskEntity, Long> {
    Optional<TaskEntity> findByUuid(String uuid);
    Page<TaskEntity> findByUserId(Long userId, Pageable pageable);
    // ... 其他 JPA 查询方法
}
```

**特点**:
- 仅在 infrastructure 层使用
- 包含 JPA 特定的注解和方法
- 不被 Service 层直接依赖

### 4. TaskMyBatisRepositoryAdapter（MyBatis 适配器）

**位置**: `infrastructure/persistence/mybatis/TaskMyBatisRepositoryAdapter.java`

预留的 MyBatis 适配器实现，用于未来切换到 MyBatis。

```java
// @Component  // 启用时取消注释
// @Primary    // 启用时取消注释
public class TaskMyBatisRepositoryAdapter implements TaskRepositoryPort {
    // TODO: 实现所有方法
}
```

## 切换持久层框架的步骤

### 从 JPA 切换到 MyBatis

#### 第一步：添加 MyBatis 依赖

在 `pom.xml` 中添加：

```xml
<dependency>
    <groupId>org.mybatis.spring.boot</groupId>
    <artifactId>mybatis-spring-boot-starter</artifactId>
    <version>2.2.2</version>
</dependency>
```

#### 第二步：创建 TaskMapper 接口

**位置**: `infrastructure/persistence/mybatis/mapper/TaskMapper.java`

```java
@Mapper
public interface TaskMapper {
    
    TaskEntity selectById(Long id);
    
    TaskEntity selectByUuid(String uuid);
    
    void insert(TaskEntity task);
    
    void update(TaskEntity task);
    
    void deleteById(Long id);
    
    List<TaskEntity> selectAll();
    
    // ... 其他查询方法
}
```

#### 第三步：创建 MyBatis XML 映射文件

**位置**: `resources/mybatis/mapper/TaskMapper.xml`

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="com.ddl.manager.infrastructure.persistence.mybatis.mapper.TaskMapper">
    
    <select id="selectById" parameterType="Long" resultType="com.ddl.manager.domain.task.model.TaskEntity">
        SELECT * FROM ddl_task WHERE id = #{id}
    </select>
    
    <select id="selectByUuid" parameterType="String" resultType="com.ddl.manager.domain.task.model.TaskEntity">
        SELECT * FROM ddl_task WHERE uuid = #{uuid}
    </select>
    
    <insert id="insert" parameterType="com.ddl.manager.domain.task.model.TaskEntity">
        INSERT INTO ddl_task (uuid, user_id, title, deadline, status, priority, progress, create_time, update_time)
        VALUES (#{uuid}, #{userId}, #{title}, #{deadline}, #{status}, #{priority}, #{progress}, #{createTime}, #{updateTime})
    </insert>
    
    <!-- 其他 SQL 语句 -->
    
</mapper>
```

#### 第四步：实现 TaskMyBatisRepositoryAdapter

```java
@Component
@Primary  // 切换为首选实现
public class TaskMyBatisRepositoryAdapter implements TaskRepositoryPort {
    
    private final TaskMapper taskMapper;
    
    public TaskMyBatisRepositoryAdapter(TaskMapper taskMapper) {
        this.taskMapper = taskMapper;
    }
    
    @Override
    public Optional<TaskEntity> findById(Long id) {
        return Optional.ofNullable(taskMapper.selectById(id));
    }
    
    @Override
    public TaskEntity save(TaskEntity task) {
        if (task.getId() == null) {
            taskMapper.insert(task);
        } else {
            taskMapper.update(task);
        }
        return task;
    }
    
    // ... 实现其他方法
}
```

#### 第五步：禁用 JPA 适配器

移除 `TaskJpaRepositoryAdapter` 的 `@Primary` 注解，或者直接删除此类。

```java
// @Component  // 注释掉
// @Primary    // 注释掉
public class TaskJpaRepositoryAdapter implements TaskRepositoryPort {
    // ...
}
```

#### 第六步：配置 MyBatis

在 `application.yml` 中添加 MyBatis 配置：

```yaml
mybatis:
  mapper-locations: classpath:mybatis/mapper/*.xml
  type-aliases-package: com.ddl.manager.domain.task.model
  configuration:
    map-underscore-to-camel-case: true
    log-impl: org.apache.ibatis.logging.slf4j.Slf4jImpl
```

#### 第七步：测试

运行单元测试确保所有功能正常：

```bash
mvn test
```

## 优势

### 1. 框架无关性

- Service 层完全不知道底层使用的是 JPA 还是 MyBatis
- 可以随时切换持久层框架，无需修改业务逻辑

### 2. 易于测试

- 可以轻松创建 Mock 实现进行单元测试
- 不需要真实数据库连接

```java
@ExtendWith(MockitoExtension.class)
class TaskServiceTest {
    
    @Mock
    private TaskRepositoryPort taskRepository;
    
    @InjectMocks
    private TaskService taskService;
    
    @Test
    void testCreateTask() {
        // 使用 Mock 进行测试
    }
}
```

### 3. 灵活的实现切换

- 可以根据性能需求选择不同的持久层框架
- JPA 适合快速开发，MyBatis 适合复杂查询优化

### 4. 代码组织清晰

- 业务逻辑与技术实现分离
- 易于维护和扩展

## 最佳实践

### 1. Service 层依赖注入

```java
@Service
public class TaskService {
    
    private final TaskRepositoryPort taskRepository;
    
    public TaskService(TaskRepositoryPort taskRepository) {
        this.taskRepository = taskRepository;
    }
    
    public TaskEntity createTask(TaskEntity task) {
        return taskRepository.save(task);
    }
}
```

### 2. 避免直接使用 JPA Repository

❌ **错误做法**:
```java
@Service
public class TaskService {
    @Autowired
    private TaskRepository taskRepository;  // 直接依赖 JPA
}
```

✅ **正确做法**:
```java
@Service
public class TaskService {
    @Autowired
    private TaskRepositoryPort taskRepository;  // 依赖接口
}
```

### 3. 适配器实现的职责

- 只负责将一个接口适配为另一个接口
- 不包含业务逻辑
- 尽可能简洁，直接委托给底层实现

## 总结

通过适配器模式，我们实现了：

1. **持久层框架的完全解耦** - Service 层与 JPA/MyBatis 无关
2. **灵活的框架切换** - 可以随时切换到不同的持久层框架
3. **易于测试** - 可以轻松创建 Mock 实现
4. **代码组织清晰** - 业务逻辑与技术实现分离

这种架构设计遵循了 SOLID 原则中的**依赖倒置原则**，使代码更加灵活、可维护和可扩展。
